# Synthetic store lifecycle and local Clear all

Run `bun --no-env-file ./tools/fixtures/device-lifecycle/run.ts` from the repository root.

The command drives `createStoreLifecycle` with the real `createStartingLocalFilterWriter` owner. One harness owns three synthetic stores: the local area, the session area and a database flag. The owner and the supervisor reach those stores through separate ports. The owner keeps its existing whole-area local reads. The supervisor gets only a marker read by name, a marker write, `remove(keys)` and key-name inventories. Its output lists every case with its seed, the result, the state, the stores at that moment, the named calls in order and a ledger.

The ledger counts constructed and live owners, writes or acquisitions that overlap a live writer, sync calls, removal and join host calls, whole-area supervisor reads and supervisor reads that name a credential key. Every case requires zero overlaps, zero sync calls, zero host calls, zero whole-area supervisor reads and at most one live owner. The supervisor's reads must each name only `pending:clear-all`.

The cases cover these situations:

- **Seeds.** Fresh, current with a held `opaqueWrite`, joined, pending join, malformed, newer layout, a crash-left marker beside a pending removal, and a newer marker beside `refreshToken`, `clientSecret` and `accessToken` names with 40 progress keys. Every seed clears to the fresh owner's `{schema: 1}` with empty session and no database.
- **Origins.** A private settings window and an unknown window clear. Popup, tab, negative window, extra fields and malformed options are refused and never join an admitted clear. A ticked request is unsupported and performs no call.
- **Faults.** Each fault applies to its port's numbered occurrence: rejected quiescence, a rejected owner stop, marker write and readback failures, partial and applied-but-rejected session clears, rejected session names, a blocked database, rejected local names before and after removal, partial and applied-but-rejected batch removal, rejected and applied-but-rejected final marker removal, rejected final names, missing key-name providers and a rejected fresh readiness. A failed stop or marker step changes no data and runs no destructive call. Every other incomplete step keeps the marker unless local is already empty. Each case restarts from serialized stores and then retries explicitly. Retryable cases also retry on the same supervisor.
- **Crashes.** Before and after the marker write, session clear, database deletion, both removal batches and the final marker removal. The harness serializes the stores at the crash, and a fresh supervisor reopens them. Every crash before final marker removal reopens blocked with no owner and no continuation call. A crash after it reopens an empty area, and the ordinary owner writes `schema: 1`. Two more cases crash at the marker write on a store with no earlier marker. Before the write, the restart keeps every original record and starts the ordinary owner.
- **Races.** Duplicate calls share one promise and one session clear. Clear all admitted while the startup marker read is held keeps one fresh owner when that read settles late. Disposal during startup starts no owner. Disposal during a clear reports disposal, keeps the marker and starts no owner. A producer write held on the owner's lane drains before the marker. Cooperative quiescence cancels scheduled callbacks. A stale owner reference returns `unavailable/disposed` after the fence.
- **Events.** An incomplete clear emits nothing. A confirmed clear emits one `cleared` event after the fresh owner is constructed, while access remains fenced through readiness. A synchronous listener shares the same clear operation. Disposal during readiness drains that owner. Clear completion settles `ready()` before a superseded bootstrap read is released.

Errors are one fixed synthetic `LifecycleFault`. Store values are synthetic. The command reads no environment, browser storage, credential or network. Producers are a cooperative fixture port, so the command proves no native writer exclusion, native key-name provider, native remove or clear atomicity, IndexedDB deletion or crash durability. Native checks are waived and unproven.

Acceptance also exercises malformed named marker records and malformed name inventories. Arrays, exotic objects and unexpected names hold startup without acquiring an owner. A throwing inventory getter reports an unconfirmed result and permits explicit retry. The CLI reports the measured case and assertion counts.

## Withdrawal observer

Run `bun --no-env-file ./tools/fixtures/device-lifecycle/run.ts --withdrawal-only` for the withdrawal observer. It uses the actual lifecycle and owner with normal, private and authenticated unknown-window settings origins. The output includes complete stores, named calls, held restart observations and Clear all results. Its repair cases exercise intent and final-write faults and restart before and after each named read and write. They prove that Device mutation follows exact intent confirmation, partial final writes stay held, and explicit reconfirmation uses the same generation. The separate consent port reads only the schema, Device and control tuple. It does not widen the marker-only Clear all port.

Run `bun --no-env-file ./tools/fixtures/account-removal-execution/run.ts --withdrawal-only` for exact removal recovery. That command creates local and synced pending records through actual accepted removal operations and withdraws through the real supervisor. It records both withdrawal writes, their held restarts, consent-only agreement, selected recovery and every serialized ledger or effect boundary. Each restart inspects without mutation and requires explicit recovery before completion. The command compares complete final local, session and sync stores and retains the terminal occurrence.

These commands cover the bounded withdrawal unit. Retained and join recovery remain unavailable. Full shard, legacy and realm acceptance require a separate frozen-source task. Native durability, ownership and exclusion remain waived and unproven. Production remains disconnected.
