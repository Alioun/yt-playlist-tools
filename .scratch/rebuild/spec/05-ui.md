# 5. UI

This chapter specifies every surface 2.0 draws: the toolbar popup, the settings page, the first-run page, the controls inside YouTube and YouTube Music, the shared playlist picker and key recorder, toasts, the brand, tokens, accessibility and the rules for UI code. It's built from tickets [09](../issues/09-where-things-live.md), [13](../issues/13-ui-stack.md), [14](../issues/14-in-page-controls.md), [15](../issues/15-popup-and-settings.md), [22](../issues/22-name.md), [24](../issues/24-performance-budget.md) and [27](../issues/27-youtube-music-controls.md), with copy taken from tickets [07](../issues/07-watched.md), [08](../issues/08-shortcuts.md), [11](../issues/11-accounts.md), [12](../issues/12-adding.md), [16](../issues/16-storage-and-sync.md), [18](../issues/18-breakage.md), [19](../issues/19-upgrade-and-rollout.md) and [26](../issues/26-youtube-music-quick-actions.md).

**Behaviour lives elsewhere.** What a feature does is in [02 YouTube](02-youtube.md), [03 YouTube Music](03-youtube-music.md) and [04 Features, accounts and data](04-features-accounts-data.md). The modules behind the views are in [06 Architecture](06-architecture.md) (§6.4.4, §6.6, §6.7), the budgets and the tests that enforce these rules in [07 Quality](07-quality.md) (§7.6, Q-TEST-18, Q-TEST-30 to Q-TEST-33), and the upgrade note's and disclosure's full copy in [08 Upgrade and release](08-release.md) (§3, §4). This chapter says where things are, how they look, what they say and how UI code is built.

**Conventions:**
- **Requirement IDs** (`UI-IA-`, `UI-POP-`, `UI-SET-`, `UI-ONB-`, `UI-YT-`, `UI-YM-`, `UI-PICK-`, `UI-TOAST-`, `UI-BRAND-`, `UI-RULE-`) are stable. Each is a testable statement. New requirements take the next free number in their group, wherever they sit.
- **Resolutions:** the main session's [resolutions](resolutions.md), all three rounds (R1–R40, R41–R67, then R68–R77), are applied, and so is R83, settled after the spec. A requirement they changed keeps its ID and ends with its R-number.
- **Words** are the [glossary](../../../GLOSSARY.md)'s. "The picker" is short for the playlist picker. "The first-run page" is `onboarding.html`, the one page that shows either first run or the upgrade note; prose never calls it "onboarding", and copy says "quick-save playlist", never "one-click playlist" (R37).
- **Placeholders:** `{Account}` is the account's name ("Unnamed account" without a label), as in every chapter (R65). `{Shortcut}`, `{Playlist}`, `{Channel}`, `{title}` and `{list}` are as in [02](02-youtube.md#conventions). Where other chapters write `{Product}`, this chapter shows the name itself, "Playlist Pigeon", because it specifies how things look; it's the same PROVISIONAL string (R65).
- **Quotes:** quotes inside copy are typographic (“ ”); straight quotes in prose only mark where copy starts and ends (R45).
- **The name is PROVISIONAL** ([ticket 22](../issues/22-name.md)). Every "Playlist Pigeon" below, the pigeon mark and the palette are placeholders until the user confirms the name. Choosing the runner-up, "Playlist Courier", is a straight string swap.
- **Precedence:** where tickets disagree, the later ticket and the main session's decisions win. Where chapters disagree, the owning chapter wins (resolutions.md's ownership rule): this chapter owns layout and visuals; behaviour and copy are 02's and 03's, accounts, settings and status behaviour 04's, mechanisms 06's, budgets and test placement 07's, and upgrade and consent copy 08's. The ones that mattered are listed under [Conflicts found](#conflicts-found).
- **Screenshots** are linked as `[NN]` per section and listed in [5.13](#513-prototypes-and-screenshots). Prototype prefixes: `wl` where-things-live (low-fi placement), `ps` popup-and-settings (hi-fi), `ip` in-page-controls, `ym` youtube-music-controls.
- **Stack:** Svelte 5 with shadcn-svelte on Bits UI, one stack with two skins ([ADR-0002](../../../docs/adr/0002-svelte-and-bits-ui.md)). The popup, settings and first-run page use the extension's own design system. In-page UI is plain Svelte with a hand-written YouTube or YouTube Music skin, and loads Bits UI only on first use.

## 5.1 Information architecture

**The rule of thumb:** the popup is "this tab, this account, right now"; settings is "everything, for good"; the page shows only what a switched-on feature draws.

- **UI-IA-01** 2.0 has exactly these surfaces:
  - the toolbar popup;
  - the settings page (`options_ui`, opened in a tab);
  - the first-run page (`onboarding.html`), opened once in a tab, showing first run after install or the upgrade note after a 1.4.5 update;
  - the in-page controls of switched-on features on YouTube and YouTube Music;
  - the toolbar badge.
- **UI-IA-02** None of these exist: a side panel, entries in the browser's right-click menu (`menus` / `contextMenus` aren't requested), new-tab or dashboard pages, and switches inside YouTube's or YouTube Music's pages.
- **UI-IA-03** Features are switched in three places only: first run (or the upgrade note), settings and the popup. In-page menus link to settings; they never switch a feature.
- **UI-IA-04** Per-account choices (which playlists) are made in the popup and shown again in settings for every account with a setup. Shared settings (feature options, keys, labels, the default percentage, Show feedback, YouTube Music's buttons) live in settings. The popup has one-click switches for the same features.
- **UI-IA-05** YouTube Music has a section switch; YouTube doesn't. It sits at the top of the popup's YouTube Music tab and in the header of Settings › YouTube Music. It's the shared, synced setting `musicSection`, **on** by default; the features inside it still start off. Off means nothing of ours runs on music.youtube.com, playlist shortcuts' "Also on YouTube Music" included, and every YouTube Music choice is kept ([YM-FEAT-5](03-youtube-music.md#1-features-switches-and-settings)). (R1)
- **UI-IA-06** The theme setting (Settings › Appearance) covers the popup, settings and the first-run page only. In-page UI follows YouTube's or YouTube Music's own look.
- **UI-IA-07** Everything a YouTube Music user needs is reachable from the popup, which also opens from the installed YouTube Music app's title bar (side panels don't open in installed-app windows).
- **UI-IA-08** The toolbar badge shows "!" when the user must act. One "!" shows at a time, the first that applies in this order (R12, R53):
  1. **consent or upgrade pending** (first run or the upgrade note): on every tab;
  2. **site access missing** for a site with a switched-on feature: on every tab, because without that site's access the extension can't tell which tabs are that site's. For YouTube Music it counts only while something that needs the access is on, with the section switch on: a YouTube Music feature, or Also on YouTube Music while Playlist shortcuts is on ([FT-46, FT-47](04-features-accounts-data.md#17-site-access-and-youtube-tabs), [FT-57, FT-58](04-features-accounts-data.md#18-the-toolbar-badge); R53);
  3. **not working:** per tab, on the tab where a feature isn't working, titled "{Feature} isn't working in this tab" ([HEALTH-15](04-features-accounts-data.md#53-where-it-shows));
  4. **a Missing or Full playlist:** on every tab.
  - **Colours:** the "needs you" reasons (consent, site access, Missing or Full) use the brand violet; "not working" uses amber.
  - Partly working (an unavailable YouTube Music action included, R50), one-off failures and anything a toast already reports set no badge.
  - **PROVISIONAL:** a per-tab tick when that tab's video was auto-added, behind the auto-add option "Tick the toolbar icon when this tab's video is auto-added", **off** until the user decides whether it exists ([for-the-user.md](../for-the-user.md); R11). The "!" always wins over the tick.
- **UI-IA-09** Deep links into settings use the hash (UI-SET-04, UI-SET-05), with kebab-case feature IDs (R32):
  - the watch-page menu's settings row → `#feature-watch-button`;
  - the popup's **Change keys** for quick-action shortcuts → `#feature-music-keys`;
  - a not-working notice's **Details**, and the popup strip's **Details** → `#diagnostics`;
  - a failure toast's **Settings** → `#feature-<id>&playlist=<playlistId>`: the feature whose playlist is Missing or Full, scrolled to that playlist's row, which is highlighted and marked with Remove (R38);
  - a sync banner's **Details** → `#everywhere`.

## 5.2 The toolbar popup

Screens: [ps-01], [ps-02], [ps-03], [ps-04], [ps-91].

### Frame and first view

- **UI-POP-01** The popup is 360 px wide and at most 600 px tall, top to bottom: header › breakage strip › at most one banner › site tabs › the tab's content (This video or Playing now, then the feature rows). There is no footer; the header's gear opens settings.
- **UI-POP-02** The first view is the header, strip, banner, site tabs and the feature switch list. It paints from one `storage.local.get` (`Backend.load()`) and never waits on a YouTube tab or the network.
- **UI-POP-03** Everything else loads on demand: unfolded rows, This video's details, the picker sheet, the account menu, and banner copy (loaded only when a banner shows; main-session decision on ticket 15). `popup.html` modulepreloads no lazy chunk.
- **UI-POP-04** The YouTube Music tab is its own chunk. When the popup opens over a YouTube Music tab, that chunk loads before the first frame.
- **UI-POP-05** Budgets (ticket 24; main session: 40 KB on both sites): first view ≤ 40 KB JS + 8 KB CSS gzip; first frame ≤ 60 ms cold (220 ms at 4×) and ≤ 40 ms warm (100 ms at 4×); each lazy chunk ≤ 45 KB; picker open including its first load ≤ 50 ms (160 ms at 4×).

### Header

- **UI-POP-06** The header is 58 px tall over a gradient hairline. It holds the mark, "Playlist Pigeon", the account in view (avatar, name, @handle) and a gear that opens settings in a tab.
  - While the account is read it shows a pulsing placeholder, never a signed-out state.
  - Before consent it shows no account at all.
  - An account with no label reads "Unnamed account".
- **UI-POP-07** With two or more account setups, in a normal window, the account becomes a menu titled "Show the setup for", listing each setup, then "This only changes what you see here. YouTube stays on the account you're signed in as.", then "Manage account setups" (→ Settings › Accounts). With one setup it's a label. No popup copy says "switch" about setups. Screens: [ps-15].
- **UI-POP-08** This video and Playing now always act as the tab's own account. Picking another setup in the header changes only which setups are shown ([ps-39]).

### Breakage strip

- **UI-POP-09** While a feature of the selected site is not working or partly working, an amber strip sits under the header with **Details** (→ settings `#diagnostics`). Over a YouTube or YouTube Music tab it covers that tab; over any other tab it covers every open tab of that site. Copy (ticket 18):
  - "{Feature} isn't working in this tab because {YouTube | YouTube Music} changed something."
  - "{N} features aren't working in this tab."
  - "{Feature} is partly working in this tab."

### Site tabs

- **UI-POP-11** "YouTube | YouTube Music" is a segmented control built as hand-written ARIA tabs with arrow-key movement. It preselects the active tab's site, else the last one used. A small gradient dot marks the site the popup was opened on (one of the gradient's seven places, UI-BRAND-06; R36).

### YouTube tab

- **UI-POP-12** On a watch page, a Short, or a YouTube page whose miniplayer is playing, the tab starts with the **This video** card: "THIS VIDEO · {title}", the status line, and **Details ›**. Its height is reserved while the serving tab answers.
  - The status line uses ticket 14's status-line strings (UI-YT-18). Paused and skipped carry inline actions: "Auto-add paused · **Resume**", "Not auto-adding this video · **Undo**".
  - When nothing is tracked, the card says what's missing (for example "No playlists for {Account} yet").
- **UI-POP-13** A **watched meter** sits in the card: a linear gradient fill with a tick per goal (each auto-add playlist's required percentage). A goal's tick turns teal once reached. The popup never uses the in-page pie.
- **UI-POP-14** **Details ›** unfolds in place: each playlist's outcome; **Don't auto-add this video** (then **Undo**, which removes the skip and checks the goal at once; R23); per auto-add playlist, **Allow** or **Deny** this channel (**Allowed** / **Denied** once listed; **Allow only** / **Deny** while that playlist's filter is off); **Save to…**. Screens: [ps-11], [ps-19], [ps-20], [ps-21].
- **UI-POP-15** Then six feature rows, in this order: Auto-add, Playlist shortcuts, Quick-save on thumbnails, Queue button on thumbnails, Watch-page button, Right-click for the video menu. Settings sync has no row.

### YouTube Music tab

- **UI-POP-16** The tab starts with the "On YouTube Music" card: the section switch (on by default, R1), with "Your features below run on music.youtube.com" when on and "Off: nothing of ours runs there. Your choices are kept." when off. While it's off, nothing else shows in the tab. The section switch never asks for site access: on Chrome, music.youtube.com access is asked from the switch of the first thing that needs it, a YouTube Music feature or Also on YouTube Music, including the click that first switches Playlist shortcuts on, whose preset turns Also on YouTube Music on (UI-POP-18, UI-POP-21, UI-POP-32; [YM-FEAT-10](03-youtube-music.md#1-features-switches-and-settings); R53, R71).
- **UI-POP-17** **Playing now** shows the playing song's art with an equaliser, its title and artist, and a split **Save | ▾** (behaviour: [YM-POP-1 to YM-POP-13](03-youtube-music.md#17-playing-now-in-the-popup)). The art is the artwork URL that `nowPlaying`'s result carries ([06 §6.2.5](06-architecture.md#625-job-catalogue); R73).
  - **When:** after consent, whenever the section switch is on and YouTube Music has site access, whichever in-page features are on, because it changes nothing on the page. (R8)
  - **Which tab:** the focused window's active YouTube Music tab, else the one playing audio, else the most recently used ([ARC-ACC-68](06-architecture.md#6211-serving-tab-routing)). (R8, R33)
  - **Nothing playing:** the row is hidden. **Signed out:** the row is one line, "Sign in to YouTube Music to save songs." (R8)
  - **States:** idle, busy, saved ("Saved to {Playlist}." with **Undo**), already in ("Already in {Playlist}."), failed ("Couldn't save: …").
  - **Under it:** "One click saves to {Playlist}", or "Your first pick becomes the quick-save playlist." while no quick-save playlist is set. (R37)
  - ▾ opens the picker sheet, loaded on demand.
  - Results show inline in the popup, never as toasts.

  Screens: [ps-03], [ps-17], [ps-47].
- **UI-POP-18** Then these rows:
  - **Quick actions:** summary = the chosen buttons joined by commas, or "No buttons chosen". Unfolded: the six button checkboxes, each with a "where" line ("Save on the player bar" reads "Shown beside YouTube Music's like, in the classic bar and the new miniplayer."), then the narrow-row warning (UI-SET-11). Screens: [ps-16].
  - **Quick-action shortcuts:** summary = up to three keycaps, then "+{N}". Unfolded: a read-only list of each action's key ("No key" when cleared), then the undo key's, which is set in Settings › Everywhere (R44), "A key acts on the song you're pointing at, else the one playing." and **Change keys** (→ settings `#feature-music-keys`; R32).
  - **Playlist shortcuts here too:** a switch for playlist shortcuts' Also on YouTube Music. With playlist shortcuts off, it's disabled and reads "Turn on Playlist shortcuts in the YouTube tab"; otherwise "They save the song you're pointing at or playing". On Chrome without YouTube Music access, switching it on asks for that access in the same click, and a denial leaves it off (a denial at Playlist shortcuts' own switch is UI-POP-32; R71); while it's on without access, it's held with "Needs site access" and **Give access** ([YM-PS-2](03-youtube-music.md#18-playlist-shortcuts-on-youtube-music); R53).
  - **Quick-save playlist**, only while a YouTube Music feature is on: "Save to playlist adds to {Playlist}" or "Not chosen: the first save asks". It opens the picker in choose mode titled "Quick-save playlist" with "Save to playlist adds songs here in one click."

### Feature rows

- **UI-POP-19** A row is at least 54 px tall: a glyph tile (violet when on, grey when off), the name, a chevron when it can unfold, a one-line summary, a health line when not working or partly working, and the switch.
- **UI-POP-20** A row unfolds in place, its content indented 54 px under the name. A switched-off row never unfolds and has no chevron.
- **UI-POP-21** A feature that's on but held shows a hatched switch and its reason: "Waiting for your OK", "Needs site access" or "YouTube Music is off". "Needs site access" carries **Give access**, in the popup and in Settings; that's also how YouTube Music features ticked at first run show when Chrome's access prompt was denied (R14).
- **UI-POP-22** Row summaries (ticket 15):
  - Auto-add: "3 playlists · adds at 50 %"; "Paused until you resume it or restart the browser" (R57); "No playlists for {Account} yet"; "Sign in to YouTube to choose playlists".
  - Playlist shortcuts: keycaps plus shortcut labels.
  - Quick-save on thumbnails: "One click saves to {Playlist}" / "Asks where to save the first time".
  - Queue button on thumbnails: "Adds to the end of the queue".
  - Watch-page button: "Under the video, before YouTube's Save".
  - Right-click for the video menu: "Right-click a video for YouTube's ⋮ menu".
- **UI-POP-23** Auto-add's row carries **Pause** / **Resume**. Unfolded, it holds this account's auto-add list (UI-PICK-20), where each ticked playlist's options open from a sliders button and its summary replaces the second line ("Shorts too · Allow only · 3"). Screens: [ps-05], [ps-06].
- **UI-POP-24** Playlist shortcuts' row, unfolded, lists each shortcut's key (the recorder, UI-PICK-23), its label and this account's playlist (a chooser; Watch later reads "Watch later (every account)"), then **Add shortcut** (it starts recording at once) and, per shortcut, a trash icon. Removing a shortcut leaves an inline "Shortcut removed · **Undo**" row in its place for 6 s; Undo puts it back as it was (R38). At most 20. Screens: [ps-07], [ps-08], [ps-09], [ps-10], [ps-14].
- **UI-POP-32** **Playlist shortcuts switched on without YouTube Music access (Chrome).** The click that first switches Playlist shortcuts on, in the popup or in Settings, also asks for music.youtube.com access, because its preset turns Also on YouTube Music on. If the user denies it, Playlist shortcuts goes on and Also on YouTube Music turns off, and "No access to YouTube Music, so shortcuts work on YouTube only." shows in place under Playlist shortcuts' row where the switch was clicked: in the popup's health-line slot (UI-POP-19), or under the Settings card's description, where a held line sits (UI-SET-07). It stays while that view is open. First run's Agree keeps UI-ONB-04's rule instead ([FT-52](04-features-accounts-data.md#17-site-access-and-youtube-tabs), [YM-PS-2](03-youtube-music.md#18-playlist-shortcuts-on-youtube-music); R71).

- **UI-POP-26** Before consent, nothing is read from YouTube: no account in the header, no This video, no Playing now, no playlist lists and no choosers. ## 5.11 Accessibility, as decided

Beyond the component library's defaults, these are the accessibility decisions. How they're checked is UI-RULE-40 and UI-RULE-41 (R38).

- **UI-RULE-01** No state is shown by colour alone:
  - failures carry an error glyph, `role="alert"` and "Couldn't …" wording;
  - every button state has its own glyph and accessible label (UI-YT-13, UI-YT-14, UI-YM-14);
  - a held switch is hatched and states its reason in text;
  - footprint tags, Missing and Full are text.
- **UI-RULE-02** Every in-page control is a native `<button>` with an accessible name. On YouTube Music the name is the action plus the item ("Play next: Giorgio by Moroder"), and tooltips give the action and its key.
- **UI-RULE-03** In-page buttons are keyboard-reachable without a per-card host:
  - YouTube: focusing a thumbnail link attaches the overlay right after it, so Tab goes YouTube's toggles → ours;
  - YouTube Music: `:focus-visible` inside a row brings the cluster, and Tab reaches ours, then YouTube Music's like and ⋮; headers are always visible.
- **UI-RULE-04** Focus is always visible: violet focus rings in the extension's pages; a 2 px white outline on YouTube Music.
- **UI-RULE-05** The extension's controls carry their roles: the switch is `<button role="switch">` with `aria-checked` state; the site tabs are ARIA tabs with arrow keys; checkbox rows are `role="checkbox"` with `aria-checked`. Whatever floats or traps focus (popover, dialog, checkbox, slider, radio) is Bits UI.
- **UI-RULE-06** Every popover and menu closes on Escape, handled inside it. Pickers are fully keyboard-operable (UI-PICK-12), and their search takes focus on open.
- **UI-RULE-07** The key recorder never traps focus: Tab and Shift+Tab move on and cancel; Esc cancels.
- **UI-RULE-08** Toasts hold while hovered or focused, and Alt+U is the keyboard path to Undo.
- **UI-RULE-09** In-page text is in the site's rem, so it follows the browser's font-size setting as the site's own text does.
- **UI-RULE-10** When a narrow YouTube Music row squeezes the title out, the tooltips and accessible names still name the song.
- **UI-RULE-11** The extension's coloured tokens keep the contrast measured on the brand sheet ([5.10](#510-design-tokens-and-measured-sizes)): primary 6.0:1 on white, success 5.7:1, warning 6.4:1 on its surface, destructive 5.9:1, and dark text 7.6:1 on dark-mode primary. Info's and the neutrals' ratios weren't recorded.
- **UI-RULE-40** **Automated checks:** axe-core runs in the real-browser layer, in both browsers ([Q-TEST-20](07-quality.md#725-layer-4-real-browser)), against the popup, settings, the first-run page and the in-page hosts on both sites. (R38)
- **UI-RULE-41** **Screen readers:** before each release, the developer does a manual screen-reader pass of the popup and settings. It's a release step, not a test ([Q-CI-18](07-quality.md#773-release-gates-summary)), and belongs in the release checklist ([08 §18](08-release.md#18-release-checklist-releasingmd)). (R38)
- **UI-RULE-42** **Reduced motion:** with `prefers-reduced-motion: reduce`, nothing of ours moves except by opacity, in the extension's pages and in-page alike: sheets, popovers and toasts fade instead of sliding, and the deep-link ring and pulsing placeholders don't animate beyond opacity. Q-TEST-20 checks it. (R38)

## 5.12 Component and build rules for UI code

### Extension pages

- **UI-RULE-12** **No class conflicts.** `cn` is `clsx` only (no tailwind-merge), so two utilities for one property resolve by Tailwind's CSS order, not by the class string.
  - A component's base classes never set a property its variants or sizes set.
  - Callers add only margins and layout; anything else is a variant or prop (e.g. `flush` on PopoverContent, `size` on Disclosure).
  - Generated shadcn-svelte components are fixed on import. Known offenders: Button's and Badge's base `border-transparent` (beat outline's `border-border`); Button's base radius, font size and icon size; Switch's `bg-none` (beat the held hatching); Input's `text-base md:text-sm` (16 px in the popup); Dialog's `sm:max-w-sm`.
  - A test enforces the rule ([Q-TEST-31](07-quality.md#726-guard-tests)).
- **UI-RULE-13** **Switches and checkboxes are controlled.** When the caller listens, they never flip themselves, so a refused or deferred change (consent first, the join question, a denied access prompt, sync full, an update-needed refusal (R13), a private window) shows the stored state. A component test covers this ([Q-TEST-32](07-quality.md#726-guard-tests)).
- **UI-RULE-14** **Each extension page builds on its own** (at least the popup gets its own build), so the popup carries no chunks shared with settings. UI-RULE-14 to UI-RULE-16, UI-RULE-19 to UI-RULE-21, UI-RULE-12, UI-POP-03 and UI-RULE-05 state [Q-PERF-35](07-quality.md#766-popup-settings-the-first-run-page-and-background)'s build rules for the UI (R52, R65).
- **UI-RULE-15** **Each page's first view is one chunk** (rolldown `codeSplitting.groups` with `tags: ["$initial"]`). Groups never import each other.
- **UI-RULE-16** **No top-level await** in an entry whose chunk lazy chunks import.
- **UI-RULE-17** **Every page must render from the build:** a real-browser test asserts that each built page renders its first view, because the size check only measures bytes (an import cycle once blanked a page while its sizes looked fine; [Q-TEST-18](07-quality.md#725-layer-4-real-browser) item 10; R52).
- **UI-RULE-18** **Focus with `preventScroll`** inside popovers.
- **UI-RULE-19** **First-view icons** are inline path data through `Glyph` (Lucide's paths, ISC); the header mark is the packaged SVG as an `<img>`; `@lucide/svelte` components appear only in lazy parts.
- **UI-RULE-20** **Two stylesheets per page:** the first view's, and one loaded with the lazy parts (`parts.css`, `settings-more.css`, `onboarding-more.css`), sharing Tailwind's layers by name.
- **UI-RULE-21** **Lean first views:** the Switch and the site tabs are hand-written; Button variants are a plain lookup joined by `clsx`; `tailwind-variants/lite` appears only in Badge, Alert and Toggle, which no first view uses; feature descriptions, the key-owner table and banner copy load outside the popup's first view.
- **UI-RULE-22** **Bits UI's `data-state`:** shadcn-svelte's generated components style `data-checked`, `data-open` and similar, but Bits UI 2.19 sets `data-state`. Map them with `@custom-variant` in the app stylesheet, or use components that match.
- **UI-RULE-23** **Dev server:** with vite-plugin-svelte 7 and rolldown 1.2, exclude svelte from the SSR optimiser, or `vite dev` breaks.
- **UI-RULE-24** **Nothing is read from YouTube before consent:** the view layer asks for the account and the tab's video only once consent is in.
- **UI-RULE-25** **The account in view only changes what's shown:** This video and Playing now always act as the tab's own account.
- **UI-RULE-26** **One seam:** views talk only to `Backend` (`load`, `watch`, `change`, `call`, `access`). Reads come from `storage.local`; writes go through the background. `access.request()` runs first in the click handler, before any await. A fake adapter drives component tests and the prototypes.

### Page UI (YouTube and YouTube Music)

- **UI-RULE-27** **No Tailwind and no shadcn styles in pages.** In-page CSS is a hand-written skin inside each component, compiled with `emitCss: false` so Svelte injects it into our shadow roots. Page scripts emit no `.css` files, and there are no web-accessible resources.
- **UI-RULE-28** **One Svelte copy per page,** in the kit. Feature files link to the kit's runtime; the generated export list uses property access (runtime names include reserved words such as `$.if`). Svelte appears only in the kits and `popovers.js`; Bits UI only in `popovers.js`, which keeps its own Svelte copy (ARC-MOD-11 to ARC-MOD-17, Q-PERF-38; R29).
- **UI-RULE-29** **Hosts** are built with `@webext-core/isolated-element` (`mode: "open"`, `isolateEvents: true`) and also stop click, pointer and mouse down/up, and `contextmenu` events, so the site never sees them.
- **UI-RULE-30** **The `all: initial` host reset:** every host placed inside the site's elements has an inline `all: initial` first (YouTube Music's card rules once stretched a host to 133 × 120 px).
- **UI-RULE-31** **Escape in popovers:** each popover handles Escape itself and stops it there (under `isolateEvents`, Bits UI never hears it, and letting it through would reach the site's own Esc).
- **UI-RULE-32** **Key state by item, not element:** per-item UI state is keyed by the item's identity (YouTube Music's queue item ID, else element plus title), and `itemInfo` is re-read after every queue job. Sites recycle elements.
- **UI-RULE-33** **No identity comparisons on `$state` objects:** Svelte proxies them, so compare by ID or element. A CI check enforces this in kit and feature code: a lint rule or a test, whichever the build chooses ([Q-TEST-33](07-quality.md#726-guard-tests); R40).
- **UI-RULE-34** **The popovers loader** has a 5 s timeout, a visible failure for every explicit open (a click or a key, UI-PICK-17) and a quiet mode for hover preloads.
- **UI-RULE-35** **Floating layers** use `strategy: "fixed"` and size to Bits UI's `--bits-floating-available-height`.
- **UI-RULE-36** **Scope and teardown:** everything a control adds (hosts, listeners, observers, timers) goes through its feature's scope. Switching a feature off removes it all at once; with every feature off, a page has zero hosts.
- **UI-RULE-37** **Constant cost:** a constant number of hosts (never one per card); delegated `pointerover` / `focusin`, never `pointermove`; no observer on the whole document; at idle no timers, rAF loops or polling; the site's own navigation events instead of `wxt:locationchange`.
- **UI-RULE-38** **Positions are re-measured** after showing where the site moves things (YouTube Music's toast at 0.4 s and 1.2 s; the watch-page button after navigation and on row changes).
- **UI-RULE-43** **Paced and bounded** ([ADR-0012](../../../docs/adr/0012-automatic-work-is-event-driven-scoped-and-paced.md)):
  - per-item state is kept for at most 200 items, oldest dropped first, however far the page scrolls;
  - resize and scroll work runs at most once per animation frame, and reads layout once;
  - an attribute observer names its attributes (`attributeFilter`), as the `<html dark>` mirror does with `dark`;
  - an observer is connected only on the page types its control appears on, and never watches the app root (`ytd-app`, `ytmusic-app`) with `subtree`: it follows the anchor's own container, or the site's own events ([Q-PERF-48](07-quality.md#768-running-cost));
  - in a hidden tab, in-page UI reads no layout, writes no DOM and keeps no observer connected. It checks once when the tab is shown again ([FT-60](04-features-accounts-data.md#13-off-costs-nothing)). (R115)

### Budgets

If it overruns its 50 KB or its first-open time (measured with no hover preload), first trim its use of Bits UI; if it still overruns, replace Bits UI in the picker with the native Popover API and a hand-written listbox (R29).
