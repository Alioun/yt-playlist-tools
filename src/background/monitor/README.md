# Monitor authoring candidate

`createMonitor` derives health for actual enabled options from the feature registry and required current facts. `statusProducer` and `noticeProducer` implement the full TabView producer's contracts. `statuses` also accepts background features through `EnabledMonitorFeature`, including browser-menu, any-tab-keys, Gather without a page script, and Sync with its own required status authority.

`MonitorAuthority.capture` must use the real Tabs context and actual visibility and fullscreen facts. Its lease must revoke on context replacement and removal. `health` must supply actual shipped routes, probes, account-key and site-core facts, anchor observations, destination facts, and background Sync status. Missing facts return unavailable. Registry metadata supplies dependencies, never current health. `subscribe` must report context, removal, owner-session and hold changes. These production bindings are absent.

`signal` validates the existing diagnostics vocabulary and shape-outline boundary. It accepts individual observations. DOM code is outside this module. `observeAnchor` accepts injected measurements and enforces settle, relevance, visibility, distinct-link and recognition thresholds. Music player-bar exceptions use `requiredHere`. `succeeded`, `measured`, `interrupted` and `reloadPassed` are explicit lifecycle inputs. Signed out, account changed, 429, 5xx, offline and recognised STATUS_FAILED use `interrupted`, never a breakage signal.

`deriveStatus` keeps required dependencies, optional dependencies and enabled Music actions distinct. One usable shipped route prevents route exhaustion. Eligible timeouts and no-effects require their consecutive thresholds. Cannot-measure is partial before its third playback and clears on a measurable playback. Gather names failed destinations and becomes not working only for its failed player or site core. Cosmetic, successful fallback and resolver ambiguity stay diagnostic. Success clears active failure evidence while preserving bounded diagnostic records.

Normal operations use the owner's `readSession` and `changeSession` methods. The existing planner merges operations into a fresh `breakage` v1 envelope. Account identity stays in that envelope and the captured revision. Signal records contain no account or content identity. The global write timestamp enforces ten-second signal pacing across engines. The planner caps persisted records at two hundred across accounts, oldest first. Operation instance identities and sequences make replay idempotent. The injected instance must be unique across active engines and restarts. A bucket admits at most two hundred instance identities per browser session. It refuses further admission rather than evicting deduplication authority. The clock must retain a browser-session time base across worker restarts.

Private journals, counters and notice-once state stay in separate memory. No private operation enters the session queue. Removal revisions discard old normal operations and private account state. Clean rejected, applied rejected, unavailable and unconfirmed writes retain their distinct owner outcomes. A rejected signal batch remains queued for an explicit later flush. There is no retry loop.

`wouldAct` creates a pending notice only when the named enabled feature would act and is not working. It batches features within sixty milliseconds. `noticeProducer.read` returns due notices without acknowledging them. Hidden and fullscreen contexts receive none. `claimNotice` requires a current actual status read. Normal claims compete atomically in the existing owner's `shown` envelope, separately from shown-once state. A claim expires after sixty seconds if its worker disappears. `releaseNotice` releases a revoked or deferred delivery. The presenter must call release when eligibility changes before display. `acknowledgeNotice` runs only after actual display. Normal acknowledgements persist through confirmed owner edits. Private delivery uses memory only. A claim never marks the notice shown.

`subscribe` reports changes. `dispose` cancels one-shot timers, unsubscribes, revokes captured reads and tokens, and clears private memory. An already invoked canonical write returns its actual outcome. No poller, storage writer, independent session lock, DOM probe, Badge, Diagnostics UI, network report or recovery toast is added.

The behavior tests, type negatives, consumer and sensitivity controls are authored and unexecuted. No runtime lease was granted. The first cannot-measure playback's feature toast, kit-free site presenter, Settings Details action, native lifecycle composition and affected-tab publication remain bindings for later units. Full TabView and registry qualification are pending. Qualification must reconcile their repairs and accepted gateway, cache and auto-add owner changes first. Native guarantees remain unproven, privacy approval is pending, activation is held, and this unit does not complete 2.0.
