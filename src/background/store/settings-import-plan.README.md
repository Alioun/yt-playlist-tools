# Settings import plan

`planSettingsImport` computes the document replacement and account cleanup for an already parsed settings file. It performs no IO and has no storage, browser, native, clock or random port. This module does not execute import.

`SettingsImportPlanInput.parsed` is the actual `ImportPlan` from `createImportPlanner`. The parser owns format, product, file completeness and trusted window privacy. The planner uses complete local and session inventories. `ImportSyncFacts` is either `off`, with no remote inventory, or `on`, with already-read sync records. A sync fact that disagrees with this browser's Device refuses planning.

`SettingsImportPlanResult` is `planned`, `refused` or `unavailable`. A refusal or unavailable result contains no executable partial batch. A planned result states `execution: "requires-owner-continuation"`. It is never a receipt, permission to write, or evidence of native atomicity.

`documents.changes` is one nonempty tuple of puts and physical account-document removals. Settings always supplies a fresh first member, even when its imported values match current values. The tuple contains every included account's replacement Setup and Filters and every omitted current Filter address. Accounts absent from the file have no document changes.

Preparation uses actual `materializeDocumentBody`, `prepareDocumentBody`, model decoders and canonical Setup context. This drops dangling targets and marks, cuts strings, and preserves full Filter tuple slots. Existing unknown fields survive under DATA-14. The actual file shapes identify owned object fields. Dictionaries and lists replace their membership. Surviving shortcut, auto-add and channel rows retain unknown extensions by ID. A missing imported handle remains a null slot when future columns follow. Envelope extensions survive replacement. Malformed or newer addressed records refuse rather than being overwritten.

The three applied preset flags retain both incoming and current true values. No preset application function runs, so imported keys and rows remain the imported choices. The file does not supply Device, consent, syncOn or native site access.

Every resulting envelope uses document version 1, the supplied nonnegative safe integer `at`, this browser's existing Device.id as `by`, and a distinct generation from the injected function. Observed local and remote generations and earlier generations in the batch cannot be reused. The function is called once for each produced live document or sync tombstone. Local physical removals produce no envelope. The deterministic fixture maps each key to `fresh:${documentKey(key)}` and binds the complete batch in its expected documents.

With sync off, document deletions are local removals and actual first-edit preparation records local edits. No remote inventory is read. With sync on, actual `planSyncWrite` receives one changed-batch with all live replacements and fresh tombstones. It receives the original full inventories, including metadata, retained chunks and unknown occupancy. It also accounts for unrelated pending outgoing documents. Canonical admission refusals stay whole-import refusals. An inventory that canonical admission cannot reconcile stays unavailable. Unrelated records are never rewritten to force admission. Pushed-history repairs precede actual first-edit preparation. Proposed sent generations are not marked pushed before a future native confirmation.

`cleanup.accounts` derives its cache, progress and conditional cleanup fields from canonical `SetupRemoval`. It includes normalized empty imported accounts even if they have no prior Setup. It never creates an empty record to retain such an account. A gather playlist or any imported kept Filter prevents removal. The actual session removal planner supplies ordered effects over shared collections. `cleanup.lastAccount` describes a conditional clear for a removed account. Other Device fields remain unchanged.

`capture` retains detached complete local, session and applicable sync snapshots. Its binding records Device.id, current consent, recognized consent control and joined identity. `expected` gives complete local and session after-values for exact verification. These snapshots include unrelated records so added Filter addresses and changed authority facts are detectable. They are planning data, with the same sensitive contents as the supplied inventory. They do not belong in logs, exported files, synced documents or diagnostics.

The future executor has these integration obligations.

1. Add one canonical owner import operation and preserve the complete owner-derived native interface. Use the accepted starting owner rather than a second writer. Require a normal trusted window and current canonical consent and authority before any write. Planning before consent grants no execution authority.
2. Re-read and compare complete inventories before acceptance. Revalidate Device, consent generation, canonical ownership, join, history, pending work and all addressed generations. A changed capture requires a fresh plan. While sync is off, perform no sync read, subscription, write or cleanup. Import is not an ARC-MSG-12 exception.
3. Design and register a durable recognized multi-account continuation that owns shared Settings, every included account's complete document replacement and every cleanup obligation. `PendingAccountRemoval` models one account and cannot represent this result. An unknown pending key ignored by startup supplies no recovery guarantee.
4. Bind the accepted before and after documents, cleanup before and after inventories, original agreement, current consent generation, join identity and canonical source epoch to that recognized continuation. Confirm acceptance by exact readback before mutations depend on it. Define permitted native effect prefixes and interrupted acceptance behavior.
5. Admit the complete changed batch again against current retained sync occupancy before ordinary local commit. Account for opaque write gates and actual native quota failures through existing canonical sync scheduling. No per-account save or partial success is allowed. Preserve tombstone retention and never spend space on anticipated old-chunk cleanup.
6. Apply document replacement separately from cleanup stages under that single continuation. Perform all cache, progress, session and lastAccount effects with exact readback. Handle rejected native calls that may have mutated data. Conditional device cleanup must preserve current unrelated device fields and authority.
7. Extend startup and consent recovery together. Restart must find the accepted operation and block conflicting mutations. Withdrawal stops work and leaves its accepted evidence inactive. A later Agree alone cannot resume it. Explicit recognized recovery needs current permissions for the exact accepted operation. Retire only after complete document and cleanup confirmation.
8. Add real-owner executor tests with crashes and ambiguous rejection at acceptance, documents, history, cleanup, withdrawal and retirement. Confirm no effect before current consent and no sync access while off. Then qualify the complete parser, planner and executor together under the coordinator's sole runtime lease.

No owner, recovery, account-removal, parser, UI, package, compiler or entrypoint source was changed by this unit. There is no protected repair proposal to apply. `settings-import-plan` has no production caller.

All compiler, focused tests, consumer, ambient-effect guard, original-format regression and behavioral control gates are authored and unexecuted. Future commands and exact control mutations are in `tools/fixtures/settings-import-plan/future-commands.json` and `controls.json`. Static installation, hashes, complete patch replay and independent rehash are recorded separately in `.audit/settings-import-plan-authoring/`.

Native durability, ownership and exclusion remain unproven. Privacy wording, rendering, axe and picker-policy holds remain open. Production activation is held. This pure plan does not complete import or 2.0.
