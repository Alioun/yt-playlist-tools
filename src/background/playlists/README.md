# Owner-backed playlists

`createPlaylists({ owner, tabs, now })` uses the canonical local owner and the actual Tabs engine. It installs no entry, storage adapter, RPC route or timer. The caller supplies a Requester authenticated by the existing native router. Neither account identity nor privacy comes from a page body.

Two cached-first interfaces were considered. An async iterator could yield cached and fetched listings, but the picker already has separate `cachedList` and `freshList` methods. The chosen `list(acct, { site, req, refresh?, originalTab? })` returns an open with `cached` and a separate `refresh` promise. It never awaits the network before returning cached rows. A caller keeps that open for the picker lifetime and consumes its pending refresh once.

Freshness includes exactly five minutes. Future and unusable timestamps refresh. Explicit refresh reads even a fresh cache. Eligible normal opens share one pending account refresh. A new account lifetime or a different original-tab constraint waits for that request to finish and then starts its own. Private and no-Setup results stay in the requesting open and never join the normal promise. A failed request preserves the cached rows and stamp and returns the original TabJobOutcome.

The existing `playlists` job supports www only. List reads and their list-present facts use that source site, including for Music display. Membership alone changes each site's independent order. Music omits Watch later; www puts the validated WL identity first. Creating and channel resolution use their existing routing rules. An original-tab constraint always uses `runIn` and never falls back.

The cache model imports only model codecs and ID validation. Storage parsing detaches values, preserves compatible unknown extensions, and removes history and identity-bearing branches. Absorption selects playlist facts explicitly. Membership retains old count and thumbnail metadata for surviving IDs; a list replaces those fields. Creation records only the confirmed ID and original validated title and privacy. Reads hide created rows at 24 hours without writing. An observed ID removes its created row.

`listAt` describes the list or membership read that last changed persisted cache facts. DATA-20 and DATA-21 identify both reads as refresh sources. DATA-57 forbids a write solely to advance a stamp, so an identical answer retains its persisted stamp. The returned fresh listing still carries its actual read time. Creation preserves `listAt`, and this module never changes `labelAt`. A created-only cached listing has a null list stamp. The protected picker seam needs the supplied nullable-stamp proposal before binding that case.

Owner captures use existing session reset and account revisions. Actual account removal revokes the account revision before cleanup. Consent, schema and authority changes revoke prior captures. Unrelated Settings edits do not. Reads use the existing read-only projection helpers and never resume pending removal. Writes share the owner lane and local port, compare first, and confirm readback. An unchanged rejection fails; applied rejection or uncertain readback stops the owner and reports uncertainty. No optimistic subscriber event exists.

`create(acct, request)` returns one caller-owned submission handle. Invalid titles can be corrected. Once submitted, every call returns the same promise, including an uncertain result. A confirmed creation remains `created` if cache persistence fails or is uncertain. The caller keeps that handle until the form is dismissed. This service neither selects destinations nor supplies playlist deletion.

`capture(acct, request)` precedes an external membership read. `absorb(scope, answer)` consumes that scope once. Successful list reads also return exact `list-present` facts. They do not clear marks. The required separate synced marks binding and the AddFlow execution wrapper are unapplied proposals in the handoff. Channel resolution calls the actual account-free job and stores no channel data. Offline channel-ID normalization and URL policy remain an explicit proposal because the frozen source has no layer-safe normalizer.

All behavior, type, consumer, control and build gates remain unexecuted in this authoring unit. The fixtures drive the real owner and Tabs with scripted native and storage ports. They provide no native identity, durability or privacy approval evidence. Tabs/projection must be reconciled against their eventual qualified return before qualification.
